# 课表导入 Word

教务系统导出的课表是 Word 文件，而课表页原先只有「拍照 → 视觉模型识别」一条路。本文记录第二条路：**直接读 Word 文件**。它不需要相机、不需要网络、不需要 API Key，所以现在它是课表页的主入口。

## 输入

同一份课表以两种容器到达，内容同构，都要支持：

| 容器 | 识别方式 | 来源 |
| --- | --- | --- |
| `.doc` | 魔数 `D0 CF 11 E0 A1 B1 1A E1`（OLE2 复合文档） | Word 97-2003，教务系统直接导出 |
| `.docx` | 魔数 `50 4B`（ZIP 包） | Word 另存为 OOXML |

`WordDocuments.read` 只看魔数分发，不看扩展名 —— 文件选择器给的 MIME 类型是自愿申报的，不可信。超过 `MAX_BYTES`（24 MB）直接拒绝，避免把堆吃光。

## 表格形状

打印出来的课表是一张 15×9 的表：

```
      c0      c1            c2      c3      c4      c5      c6   c7   c8
R1          节次         星期一  星期二  星期三  星期四  星期五  星期六  星期日
R2   无节次   0         ,深度学习1班[2-18周]朱红艳[]
R3   上/午   08:30-09:10
R4  (合并)   09:15-09:55                中国式现代化的理论与实践（电子1班）[3-11周]马希[]
...
R12  晚/上   18:20-19:00                        工程计算…[11-18周]曾上游[]    深度学习1班[3-17周]夏海英[]
```

- **c0/c1 是节次栏**：c0 是 `上午/下午/晚上`（纵向合并）或 `无节次`，c1 是时间段。
- **c2…c8 是一个星期的七天**，课程就写在这里。
- **课程格语法**：`课程名[周次]任课教师[上课地点]`。方括号是唯一的分隔符，所以教师和地点都可以为空（样本里地点全部为空 —— 这正是「导入后自己补上课地点」这条需求的来源）。

### 节次号

`节次` 栏写的是时间段（`08:30-09:10`），不是编号。**节次号 = 去掉无节次行之后，数据行的 1-based 序号**：

```
上午 5 行 → 第 1-5 节
下午 4 行 → 第 6-9 节
晚上 4 行 → 第 10-13 节
```

这与视觉识别那条路的契约（`上午1…上午5`、`下午6…下午9`、`晚上10…晚上13`）完全对齐，两条路产出的课表因此可比。

### 无节次行

`无节次` 是学校给「还没排时间」的课留的行。它**不是第 0 节**：本机课表从第 1 节开始，这一行整行不导入。被丢掉的课程数会报给用户（"已从 Word 导入 7 门课程，忽略「无节次」行的 1 门课。"），不静默吞掉。

### 纵向合并

一门课跨几个时段时，打印稿用纵向合并表达。这不是装饰 —— 它是跨度信息的唯一来源。`WordCell.continues` 就是这个语义：`true` 表示「这一格是上面那格的延续，课程继续上」。

## 统一契约

两条 reader 产出同一种结构，导入器只认这个结构：

```kotlin
data class WordCell(val lines: List<String>, val continues: Boolean = false)
data class WordTable(val rows: List<List<WordCell>>)
data class WordDocument(val tables: List<WordTable>)
```

`lines` 是格内的段落，手动换行也算一段 —— 所以节次栏的 `上\n   午` 会原样保留成两段，而不是被折成一个空格。

## 两条读取路径

### `.docx`

`ZipInputStream` 取 `word/document.xml`，`DocumentBuilderFactory` 解析（关掉 DOCTYPE 与外部实体，防 XXE）：

- `<w:tbl>/<w:tr>/<w:tc>` → 表/行/格；段内 `<w:p>` 与 `<w:br/>` 都断行。
- `<w:tcPr><w:vMerge w:val="restart"/>` 是合并起点（`continues = false`，**即使格内无文本** —— 样本里大量「空的 restart 格」，它们就是矩阵里的空单元格）；`<w:vMerge/>` 才是续格（`continues = true`，`lines` 为空）。
- `<w:t>` 文本原样取，不按 `xml:space` 分支：有的导出器不加该属性却仍有前导空格。

### `.doc`

Word 97-2003 二进制，全部手写，无第三方依赖：

1. **CFB/OLE2**：header → FAT/DIFAT → 目录项 → mini stream / mini FAT。表流按 FIB 的 `fWhichTblStm` 取 `1Table` 或 `0Table`。
2. **正文**：`fcClx` → PlcPcd 分片表 → 每片 `fc` 的 bit30 决定 8-bit 还是 16-bit UTF-16LE。还原出的字符数必须等于 FIB 的 `ccpText`。
3. **段落边界**：`PlcfBtePapx` → FKP 页 → `rgfc` 给出全部段落边界。用来把表格**之前**的正文段落排除在首格之外。
4. **行与合并**：行定义在 **`Data` 流**，是 `行数` 条定长记录（本样本 15 × 505 = 7575，逐字节铺满）。每条含 `sprmPFTtp`(0x2417) 与 `sprmTDefTable`(0xD608)：`itcMac` 是列数，`rgdxaCenter` 是列宽（与 .docx 的 `tcW` 逐列吻合），随后是每格 20 字节的 TC。**`continues` 由 TC 的标志位判定**：

   ```kotlin
   continues = ((flags shr shift) and 1) == 1 && ((flags shr (shift + 1)) and 1) == 0
   ```

   本文件族的 TC 布局用 bit5/bit6；MS-DOC 规范布局是 bit3/bit4，按 TC 第二个字是否为 0 自动选。

5. **自校验**（写进实现，不是只在测试里）：每条记录必须恰好消耗「自报的 itcMac 个格 + 1 个空行标记」，且恰好用完全部格；任一不成立就整条 TAP 路线返回 null，落到结构推断分支，**绝不静默乱配**。

> 一个踩过的坑：`0x07` 在字符流里既是**格结束**也是**行结束**，字符相同、无法从文本区分。第一版做过全字节签名扫描找 `sprmPFTtp`/`sprmTDefTable`，在 `WordDocument` 与 `1Table` 里 0 命中，一度被判定为「格式不携带合并信息」。实际是**扫错了流** —— 行 TAP 在 `Data` 流里。字符流的真实结构是每行整齐的「9 个格标记 + 1 个行标记」，但合并续格与「这节没课」逐字节相同，所以字符流确实给不出跨度。

## 导入器

`TimetableWordImporter.read(document, term, recognizedAtMillis)`：

1. 找课表表格：表头行里出现 ≥3 个星期名的那张表；取星期列最多的那张。
2. 节次栏 = 第一个星期列左边的所有列；判定「无节次行」看节次栏里有没有时间段或 `第 N 节`。
3. 逐行取节次号（显式 `第 N 节` 优先，否则按行序累加），逐列把课程格语法解成 `TimetableCourseDraft`；`continues` 的格延上一门课的结束节次。
4. 全部草稿交给 **`TimetableValidator`** —— 与视觉识别同一条校验：范围检查、去重、冲突拒绝。**没有第二套规则**。

所以「导入的课表」和「识别的课表」在模型层完全等价，后续每一处（周切换、今日课程、网格、编辑、持久化）都不需要知道它是从哪来的。

## 入口与编辑

- **导入 Word 课表** 是 `EmptyTimetableCard` 的主按钮，也是 `课表管理` 的第一项；`选择图片` / `拍照` 降为次要按钮。理由写在代码注释里：导入是课表本来的出处，也是唯一不需要相机、网络和 API Key 的入口。
- 文件读取走 `WordImportFiles.readAtMost`（按块读、超限即停），不用 `readBytes()` —— provider 谎报长度时前者不会把堆吃掉。
- 导入之后，「添加课程 / 编辑这门课 / 删除这门课」全部可用（`课程管理` 卡片与课程详情页）。**上课地点**就在编辑器里，改完保存即落到本机；这正是这个功能要解决的问题 —— 教务系统打印的课表不写地点。

## 真值与回归

样本与真值都在 `app/src/test/resources/word/`：

- `课表打印.doc` / `课表打印.docx` —— 同一份课表的两种容器（后者由 Word 从前者另存）。

## 已知边界

如实记录，未粉饰：

1. **`.doc` 里行 TAP 的位置不唯一**。本样本的 TAP 在 `Data` 流；Word 本体写小表时可能把行属性放在 FKP 的 PAPX 里，本读取器不解析那部分。这种情况会落到结构推断分支：**文本仍然精确，`continues` 变成推断值**。推断分支的偏差已被钉死（把样本的 `Data` 流改名后，推断与真值恰好只差 R11C4 一格）。
2. **未验证**：多表格文档（实现把所有行记录汇成一张表）、8-bit 压缩分片路径、MS-DOC 规范 TC 布局（bit3/bit4）。
3. **多表格**没有 fixture，所以「每表一项」这条契约没被验证。
4. 导入的课表 `term` 是空串 —— `WordDocument` 只暴露表格，标题段落在契约之外；界面不渲染 `term`。
5. 文件选择与 Compose 层的手势（按钮 → 系统文件选择器 → 导入）没有 instrumented 测试，本项目没有 Robolectric / compose-ui-test 依赖；那一段是编译通过 + 代码审阅级别。
