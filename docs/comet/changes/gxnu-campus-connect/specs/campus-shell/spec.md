# 校园应用外壳完整目标规格（Shape 草案）

首期交付 Android 校园网 App 和可扩展应用基础。Windows 排第二、iPhone 排第三，本期保存后续路线和接口边界，不把后两者算作已经支持。

首期安装产物为 APK，支持 Android 8.0 及以上（minSdk 26），compileSdk/targetSdk 34，在本机 Android 14 模拟器验证。设备网络能力和界面分层，构建版本在不改变用户行为时可调整以解决工具兼容性。

## SHELL-1：稳定信息结构

移动端采用首页、服务、我的三个入口。首页突出网络状态和一个主操作；服务展示可用模块；我的管理账户、连接策略、主题与诊断。桌面首发时保留相同业务结构并采用适合桌面的导航与系统入口。

首期只有已接入的校园网是可操作服务。未接入的课表、成绩、校园卡、图书馆或缴费不展示虚假数据和成功结果。后续路线保存在设计文档，不假定学校已有接口或不同服务共用密码。

## SHELL-2：离线与首屏容量

核心界面、图标和字体依赖随本地安装资源提供，未认证时无需访问外部 CDN。主要状态和连接按钮在目标平台普通首屏可见；长列表、帮助与诊断通过专门页面或受控区域展示。

移动布局处理系统安全区域、键盘、窄屏及大字体，主要触控区域至少 48 dp。桌面如纳入首发，在 1280×800 下可完成主操作且无横向溢出。不得通过裁掉控件或缩小正文牺牲可读性。

## SHELL-3：视觉与可访问性

浅色与深色共享语义颜色，采用单一蓝色主操作、软灰背景、卡片层次、细线图标和一致间距。状态使用文字和图形；普通正文对比至少 4.5:1。表单与图标操作有可访问名称，辅助工具能理解其状态。

过渡解释连接过程与操作反馈，不用装饰性长动画拖慢高频连接；尊重减少动画偏好。Mobbin 参考记录实际查看的页面及可见范围，不宣称已查看不可访问流程。

## SHELL-4：模块扩展

应用外壳、服务注册、网络协调、GXNU 协议适配器与设备能力桥职责独立。页面不直接拼接带账户密码的认证 URL。

后续通过模块描述、路由及各自数据适配器接入；某个服务异常不阻止网络模块打开，新增服务无需改写 GXNU 认证核心。预留明确边界，不提前建立未需要的云端账户或插件下载系统。

## SHELL-5：本机模拟器预览

交付 APK 与可复用的构建、安装和启动入口。检测本机可用安卓模拟器，将产物自动安装并打开，减少手动复制 APK。优先使用现有兼容模拟器；环境缺失或 ABI 不兼容时明确诊断并提供实际可行的预览路线。

模拟器的虚拟网络不自动等同于物理手机的校园 Wi-Fi。可在模拟器检查界面、账号、运营商与各连接状态；真实自动认证最终依据目标校园 Wi-Fi 的网络验证，不能以宿主电脑已上网判定 App 验收通过。
