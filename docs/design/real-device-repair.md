# Android 0.2.0 连接修复

本轮源于用户实际手机测试：无法认证、没有可辨认的结果、明显卡顿。上一版的模拟器画面和编译结果没有证明真机认证可用。本轮修复连接链路、响应解析、存储线程和反馈界面；真实校园认证仍需实体 Android 在 GXNU-YC 上验证。

## 已复现与修复

- 首次点击原先刷新 Wi-Fi 后立即读取旧权限状态。现在保留一次手动连接意图，立即显示准备状态，等待实际识别；授权后继续，取消后不续接。读取失败不会使用旧网络提交。
- 未认证 Wi-Fi 可能让外网探测超时。初次检查最多 2.5 秒，失败后继续学校认证；学校认证最多 30 秒，最终验证最多 10 秒，协调器整体最多 45 秒。网络识别另有有限等待。
- 同一 Wi-Fi 的能力变化与身份变化分开处理。临时未知 SSID、较晚返回的旧读取和旧扫描不能覆盖已经确认的当前网络；换网和真正撤销权限仍使旧结果失效。
- 已在线会话失去验证能力后可以进行一次自动恢复；账号错误、相同事件和用户取消不会触发连续提交。
- 发现页可跟随最多三次同学校 HTTPS 重定向，优先读取最终 URL 的终端参数。必要时通过学校只读 chkstatus 补齐地址，支持 ss3 十六进制 IPv4；不编造终端 IP 或 MAC。凭据请求不跟随重定向。
- 学校 ret_code 分类保留：账号拒绝、学校超时、系统忙和参数缺失各有提示。学校回显中的账号、密码和链接会处理后才显示；已在线响应仍需验证同一个 Wi-Fi。
- 外网验证采用可信 HTTPS 204 的回退探测，一个入口被过滤时尝试另一个。登录页、重定向和非 204 不算成功，所有请求仍绑定目标 Android Network。
- Keystore、凭据恢复/保存/删除与设置写入进入串行 IO 队列。保存期间撤销旧内存凭据并暂停自动配置；较早保存不能覆盖较晚删除。请求取消把阻塞 disconnect 留在 IO，调用线程可以立即继续。
- 首页常驻显示连接结果与恢复操作，全局通知按连接尝试发布一次。旧通知的关闭动作不会清除新结果。忙碌时显示真实阶段、圆环、等待秒数和取消入口。

## 真机定位

用户已确认测试手机为红米 K80，Wi-Fi 名称是 GXNU-YC。后续反馈 0.2.0 仍提示学校配置响应异常，输入也有卡顿。短暂 USB 调试会话读取到设备型号 24117RK2CC、Android 16；会话随后断开，未取得 App 的实际失败响应。用户要求结束 USB 排查并直接修复软件。

安装 0.2.1 后，在手机连接 GXNU-YC，并按实际校园账号设置供应商。点击连接后查看首页的具体原因；「我的 → 网络诊断」包含应用与 Android 版本、当前 Wi-Fi、错误建议及本次连接阶段和耗时。

如仍无法认证，保留首页提示以及诊断末几行即可；本次手机型号与 Wi-Fi 名称已经确认。USB 调试连接后可直接检查手机上的错误；模拟器和已联网电脑的结果不能替代手机认证证据。

## 0.2.1 的配置与输入修复

再次只读取学校 loadConfig 和 chkstatus，未发登录或注销请求。已在线电脑的 loadConfig 返回 code=1，使用 UTF-8 JSONP；有无 jsVersion 的两份样本均能被浏览器解析。此证据不能确定手机未认证时返回的响应，也不能把补齐请求元数据认定为已确认的真机根因。

学校 a41.js 为 JSONP 附加 jsVersion、lang 和随机 v。App 原先的 loadConfig 请求遗漏了这些字段；0.2.1 已按发现的脚本版本补齐，并为只读终端状态请求加入语言字段。保留同一目标 Wi-Fi、学校 HTTPS 白名单与严格数据解析；没有放宽不支持的认证或验证码配置。

原来的「学校配置响应格式异常」同时可能来自 chkstatus 和 loadConfig。现在分别显示「终端状态」与「认证配置」，解析异常只保留行、列数字；HTTP 异常显示状态码，不显示原始 JSON、异常正文、账号密码或完整请求 URL。诊断页增加当前安装版本，便于确认是否正在使用新版。

账号与密码分别在独立的 Compose 字段范围读取输入状态；表单只在校验状态变化时更新。密码显隐、转换器及键盘设置复用，账号仅提交时去除首尾空格。保留即时输入、密码字符、空值错误、保存完成后返回和失败保留输入。已消除字符编辑时重组周围表单的已知路径；K80 的实际输入延迟仍需设备检查。

新增测试使用完整脱敏学校配置与内存 HTTPS seam，不实际提交账号。首次定向执行 4 项，真实配置兼容测试通过，请求元数据与两项阶段提示测试共 3 项实际断言失败；日志为 D:\gxsf-workflow-temp\school-response-red.log。修复后 PortalClientTest 20 项和新增 4 项全部通过，0 失败、错误或跳过，当前 UI 与网络实现的编译同时成功；日志为 D:\gxsf-workflow-temp\school-response-green.log。完整测试、打包与 lint 交由 Runtime 在冻结候选后执行。

0.2.0 普通模式已实际核验测试账号加密保存、供应商保存和重启恢复，保存约 1,048 ms、恢复约 1,214 ms，均在模拟器上测得。三次 Activity 冷启动显示耗时为 10,141 / 2,718 / 2,170 ms，不能代表全部异步初始化。保存期间 gfxinfo 为 33 帧、22 帧超期，不能声称模拟器或 K80 已不卡。之后的导航检查在第 2 轮被中断，删除阶段未执行；测试账号留在专用模拟器中，后续恢复该设备时需要删除。以上结果不是 0.2.1 真机认证证据。
